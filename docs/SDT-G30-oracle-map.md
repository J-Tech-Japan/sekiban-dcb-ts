## Repeating B0

1. Complete every runtime/config/tool/test/doc update and run `npm run test:g30`.
2. Seal one final C containing all G30 material, calculate its runtime and
   deployment-config digests, and run the candidate checker against C.
3. Supply only file-fed conformance and observability tokens; run
   `npm run deploy:g30:b0`. It derives the telemetry query from the B ledger
   and accepts no activation/outlier declaration. It performs only dry-run/deploy/
   measurement work on the existing G32 service and never creates, wipes,
   migrates, or reseeds storage.
4. The recorder writes R evidence only. R may change evidence files matching
   the above glob and append C exactly once in `ci.yml`; any other diff needs a
   new C and a full repeat.

The evidence records all four outlier hypotheses as attributed or excluded
with joined raw observations. It never accepts a human declaration, labels a
time-derived activation cause, or turns B0 overhead into a performance pass/fail.
