## Result

The real allocator → Tag → D1 → G44/G62 proof reproduces a live strict-order
defect. It is not safe to implement the first-arrival fence in this checkpoint.
The proof allocated a lower-SUID and a higher-SUID candidate in one allocator
request (one allocator lineage), appended/delivered the higher candidate first,
and ran the actual safe-lane path without injecting a `SETTLED` result. G44
reported the normal `BLOCK/UNSETTLED` intermediate state and the real safe pass
later recorded `SETTLED`/completed for the higher event. The lower candidate was
then appended and delivered; the lower SUID arrived after the projection
checkpoint. The new detector recorded `LATE_LOWER_SUID`, appended an ordering
incident, and made the subsequent safe pass fail closed.

This proves that an allocator can issue a lower SUID which is not yet in the
Tag/D1 source universe when a higher SUID is admitted. A first-arrival fence
would therefore certify an unsafe frontier in this observed shape. No
first-arrival fence, SafeWindow change, retry/drain change, G44/G62 semantic
change, production change, or G32 change was made. The live defect is preserved
for the G69 design decision rather than hidden by a synthetic `SETTLED` result.

## Scoped implementation

- `MaterializedViewCatchUp` now asks the projection source for a lower SUID
  whose `FirstArrivedAt` is after the checkpoint update. If found, it records a
  deterministic `ORDER_VIOLATION` incident and throws a fail-closed MV error.
  Ordinary replay of an event already present before the checkpoint is excluded
  by the first-arrival comparison.
- `D1EventStore.findLateLowerSuid` is the real D1 detector used by the proof.
- The lag-estimate observation no longer excludes a lower-SUID arrival merely
  because a higher SUID is already present. The existing decayed estimate can
  therefore observe the actual arrival/replay rather than silently dropping it.
- `D1EventStore.recordDelivery` now leaves one append-only diagnostic admission
  receipt per attempt, including source, queue/attempt identity, allocator
  lineage, obligation sequence, enqueue/arrival/observation clocks, before/after
  first/last arrival values, status, retry reason, and clock origin. The receipt
  table is diagnostic-only and best effort; no delivery, retry, G44, MV, or
  public-read decision consumes it.
- Added migration `0015_g69_admission_attempts.sql`, the G44 test migration hook,
  a real `test/g69-ordering.spec.ts`, the source-aliasing
  `vitest.g69.config.ts`, and the `test:g69` script.

No first-arrival fence or runtime ordering workaround was implemented.
