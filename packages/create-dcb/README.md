# @sekiban/create-dcb

Create a named Cloudflare starter with a visible booking demo:

```sh
npx @sekiban/create-dcb my-booking-app
cd my-booking-app
npm install
```

From a checkout of this repository, run the generator directly:

```sh
node packages/create-dcb/bin/create-dcb.mjs my-booking-app
```

The CLI slugifies the project name to lowercase hyphenated form, writes into
`./<slug>`, and refuses an existing non-empty directory. It does not publish
the package or create Cloudflare resources.

After generation, follow the project's [DEPLOYMENT.md](template/DEPLOYMENT.md)
for the complete topology, offline `npm run deploy:check`, and future
deployment steps. The generated check creates no Cloudflare resources.

The generated Worker mounts only the maintenance prefix under
`/internal/sekiban`. Application commands and reads call the runtime
in-process. The stock `deploy:check` attests the exact maintenance-only mount.
Added runtime paths or prefixes, or re-enabled serialized forwarding, fail
before Wrangler. An intentional customization must update the gate, receipt
expectations, route tests, and applicable runbook policy together. Projects
generated by earlier versions can match the new default by setting
`forwardSerializedRoutes: false` while retaining the `/maintenance` extra
prefix.

The generated topology carries `REPAIR_OPERATOR_TOKEN` as a conditional
external prerequisite. It is optional while `/operator/*` stays unmounted and
the Worker does not export runtime fetch directly. Adding `/operator` routes
provisions `REPAIR_OPERATOR_TOKEN` through Wrangler and updates the gate,
receipt expectations, route tests, and applicable runbook policy together.
Until that coordinated change, the stock gate reports `generated runtime mount
is not maintenance-only` before Wrangler. A default export that is not the
single const `composeHandlers` call is an unresolved source shape before
Wrangler. Do not put the value in source, topology, `vars`,
generated output, command arguments, or logs. `deploy:check` reports that
source state and does not verify remote state. The stock mount has no
`extraPaths` member and one `extraPrefixes` entry.

The sample composition proof and generated `deploy:check` share one copied,
byte-checked offline validation core. The starter imports only its local copy
and keeps `deployment-topology.json` as its sole deployment data authority;
the shared core does not reconcile declared files with live Cloudflare state.

The template's keyed room read returns `lastSortedUniqueId`. That correction
is in this repository's template and reaches npm with a later
`@sekiban/create-dcb` release. The published `0.1.3` creator is unchanged.

The generated project includes `cosmos.experimental.json` as an experimental,
read-only layout and binding descriptor. It does not activate Cosmos: the
generated worker and Wrangler configuration continue to use D1 until the
consumer explicitly changes source composition.
